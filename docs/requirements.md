# agent-code-sandbox 要件定義（ドラフト）

## 目的

Node.js で作る AI エージェントが、LLM の生成したコードを安全に実行できるようにするライブラリ。OS の分離機構に頼らず、VM 上の実行環境（Amazon Bedrock AgentCore Runtime など）でもそのまま動くことを最優先にする。

## 解決したい課題

- Node.js 自体には、信頼できないコードを安全に動かす仕組みがない
- AgentCore Code Interpreter のようなマネージドなサンドボックスは分離が強すぎて、ホストのファイルや関数を渡したり、通信先をドメイン単位で許可したりできない
- 既存の OSS のサンドボックスは namespace・seccomp・root 権限など OS の機能に依存していて、microVM やコンテナの中では動かないものが多い

## 想定する利用者とユースケース

- 利用者：Node.js（TypeScript）でエージェントを実装する開発者
- ユースケース
  - データの加工・集計・ファイル生成を、LLM が書いたコードで行う
  - LLM が書いたコードから、許可した外部 API を呼ぶ
  - LLM が書いたコードから、ホスト側で定義したツール（DB 検索など）を呼ぶ

## 脅威モデル

- 攻撃者：プロンプトインジェクションなどで、実行されるコードを操作できる者
- 守るもの
  - ホストプロセスの秘密情報（環境変数、IAM 認証情報、メタデータのエンドポイント）
  - 許可していないファイル
  - 許可していない通信先（データの持ち出し先）
  - ホストの可用性（無限ループやメモリの食いつぶし）
- 守らないもの
  - ランタイム（V8 など）の脆弱性を突いた脱出。これは外側の VM の分離に任せる
  - 互いに信頼しないテナントを同じプロセスで動かすこと

## 機能要件

### 実行

- JavaScript / TypeScript のコードを文字列で受け取って実行できる
- 標準出力・標準エラー・終了状態・戻り値（JSON にできる値）を返す
- npm パッケージを使える（事前に許可・キャッシュしたものだけ）

### ファイル

- 実行ごと（またはセッションごと）に作業ディレクトリを持つ
- 読み書きできるパスを許可リストで指定できる
- 実行前にファイルを置く／実行後に生成ファイルを取り出す手段がある

### ネットワーク

- 通信先をホスト名（とポート）の許可リストで指定できる。既定は全拒否
- 拡張：パス・メソッド単位の制御、通信ログ、認証ヘッダーの注入（コードに API キーを渡さない）

### ホストのツール呼び出し

- ホストが定義した関数を、サンドボックス内のコードから呼べる
- 渡した関数以外のホストの機能には触れられない

### 資源の制限

- 実行時間の上限（超えたら強制終了）
- メモリの上限
- 出力サイズの上限

## 非機能要件

- 動作環境：Linux（x86_64 / arm64）の VM・コンテナ、macOS（開発用）。root 権限や特別なカーネル機能を必要としない
- AgentCore Runtime 上で動作を確認する
- 配布：npm パッケージ。利用者が別途ランタイムを手動インストールしなくて済む
- 起動のオーバーヘッド：1 回の実行あたり数百 ms 以内を目安にする

## スコープ外（初版）

- Python など JS / TS 以外の言語
- シェルコマンドや任意のバイナリの実行
- GPU や長時間動き続けるプロセス

## 未決事項

| 論点 | 案（推奨を先頭に） |
|---|---|
| 状態の持ち方 | 1 回ずつ独立して実行し、作業ディレクトリだけをセッションで共有する ／ REPL のように変数も保持する |
| ツール呼び出しの経路 | localhost の HTTP ／ 標準入出力の RPC |
| npm パッケージの扱い | 事前にキャッシュしたものだけ許可する ／ 実行時に registry から取得する |
| Python 対応 | 初版では扱わない ／ Pyodide で対応する |
