# agent-code-sandbox 要件定義（ドラフト）

## 目的

Node.js で作る AI エージェントが、LLM の生成したコードを安全に実行できるようにするライブラリ。OS の分離機構に頼らず、VM 上の実行環境（Amazon Bedrock AgentCore Runtime など）でもそのまま動くことを最優先にする。

## 解決したい課題

- Node.js 自体には、信頼できないコードを安全に動かす仕組みがない
- AgentCore Code Interpreter のようなマネージドなサンドボックスは分離が強すぎて、ホストのファイルを見せたり、通信先をドメイン単位で許可したりできない
- 既存の OSS のサンドボックスは namespace・seccomp・root 権限など OS の機能に依存していて、microVM やコンテナの中では動かないものが多い

## 想定する利用者とユースケース

- 利用者：Node.js（TypeScript）でエージェントを実装する開発者
- ユースケース
  - データの加工・集計・ファイル生成を、LLM が書いたコードで行う
  - LLM が書いたコードから、許可した外部 API を呼ぶ

## 設計方針

- LLM にとって使いやすいことを優先する
- 実行は 1 回ずつ独立させ、変数などのメモリ上の状態は持ち越さない。次の実行に引き継ぐのは作業ディレクトリのファイルだけにする
  - LLM は 1 回で完結するスクリプトを書くのが得意で、途中の結果をファイルに書き出す使い方にも慣れている
  - プロセスが落ちても「どの状態が生きているか」で LLM が混乱しない
  - 実行ごとに許可するドメインやパッケージを変えられる

## 提供形態

Node.js ライブラリとして、関数を提供する。MCP サーバーなどの形では提供しない。

API のイメージ（名前や形は設計で決める）：

```ts
const result = await exec({
  code: "...",                         // JS / TS のコード。entrypoint とどちらか一方を指定する
  entrypoint: "main.ts",               // 作業ディレクトリ内のファイルを実行する場合
  packages: ["papaparse@5"],           // 使う npm パッケージ
  allowedDomains: ["api.example.com"], // 通信を許可する先
  workdir: "/tmp/session-123",         // 実行をまたいで共有する作業ディレクトリ（読み書きできる）
  readonlyPaths: ["/data/uploads"],    // 読み取りだけ許可するパス
  timeoutMs: 30_000,
});
// result: { stdout, stderr, exitCode }
```

## 脅威モデル

- 攻撃者：プロンプトインジェクションなどで、実行されるコードを操作できる者
- 守るもの
  - ホストプロセスの秘密情報（環境変数、IAM 認証情報、メタデータのエンドポイント）
  - 許可していないファイル
  - 許可していない通信先（データの持ち出し先）
  - ホストの可用性（無限ループやメモリの食いつぶし）
- 守らないもの
  - ランタイム（V8 など）の脆弱性を突いた脱出。これは外側の VM の分離に任せる
  - 互いに信頼しないテナントを同じプロセスで動かすこと

## 機能要件

### 実行

- JavaScript / TypeScript のコードを、次のどちらかの形で受け取って実行できる
  - コードの文字列
  - 作業ディレクトリ内のファイルのパス。LLM がエージェントのファイル編集ツールでコードを書いて直し、実行だけを `exec` で行う使い方を想定する
- 実行するコードから、作業ディレクトリ内のほかのファイルを相対パスで import できる
- 標準出力・標準エラー・終了コードを返す
- エラー時は、LLM が直せるだけの情報（例外のメッセージ、行番号）を標準エラーに出す

### パッケージ

- 実行ごとに npm パッケージを指定でき、実行時に registry からダウンロードする
- パッケージを取得する段階とコードを実行する段階を分け、registry への通信をユーザーのコードから使えないようにする
- パッケージのインストールスクリプト（postinstall など）は実行しない
- 一度ダウンロードしたパッケージはキャッシュし、次の実行では再取得しない

### ファイル

- 書き込めるのは作業ディレクトリの中だけ
- 作業ディレクトリのほかに、読み取りだけを許可するパスを指定できる（入力データや参照用のドキュメントを、コピーせずに見せるため）
- シンボリックリンクなどを経由して、許可していないパスに届かない
- 作業ディレクトリは実行をまたいで共有でき、ホストから直接ファイルを置いたり取り出したりできる

### ネットワーク

- 通信先をホスト名（とポート）の許可リストで指定できる。既定は全拒否
- 拡張：パス・メソッド単位の制御、通信ログ、認証ヘッダーの注入（コードに API キーを渡さない）

### 資源の制限

- 実行時間の上限（超えたら強制終了）
- メモリの上限
- 出力サイズの上限（超えた分は切り詰め、切り詰めたことを示す）

## 非機能要件

- 動作環境：Linux（x86_64 / arm64）の VM・コンテナ、macOS（開発用）。root 権限や特別なカーネル機能を必要としない
- AgentCore Runtime 上で動作を確認する
- 配布：npm パッケージ。実行に必要なランタイムは初回の実行時に自動でダウンロードし、利用者の手動インストールを不要にする
- 起動のオーバーヘッド：キャッシュが効いている状態で、1 回の実行あたり数百 ms 以内を目安にする

## スコープ外（初版）

- Python など JS / TS 以外の言語
- 変数を次の実行に持ち越す（REPL のような）実行
- サンドボックス内のコードからホストの関数を呼ぶこと（必要になったら、プロセス間通信で JSON をやり取りする形で足す）
- MCP サーバーなど、Node.js ライブラリ以外の提供形態
- シェルコマンドや任意のバイナリの実行
- GPU や長時間動き続けるプロセス
